# find_skills：内置 skill 发现模块

这是技能包自带的发现流程，不依赖另装同名 skill，也不假装环境里存在名为 find_skills 的工具。如果环境已有 find-skills，可借助其检索能力，再遵守这里的学习用途与选择规则。

## 先把领域转成可搜索任务

从用户话里提取领域、要学会的工作、经验水平。把中文需求转换为对应的中英文专业词与具体任务，如“用户研究 / user research / interview synthesis”，以结果调整关键词。信息足够时直接搜索。

## 发现候选

优先使用当前可用的联网检索或 GitHub 连接器：

1. 查 skills.sh 的相关目录、搜索结果及榜单，定位具体 skill 页面。
2. 在 GitHub 检索相关仓库和 SKILL.md，例如“主题 + agent skill / SKILL.md”，核对源仓库与实际技能路径。
3. 对与目标有关的结果，查看真实星数、更新记录及源文档。浏览器结果不显示星数时，可用公开 GitHub API 的仓库接口读取 stargazers_count 与 pushed_at；不可据搜索摘要推算精确值。

如已具备 Skills CLI，也可用官方命令检索：

    npx skills find <任务关键词>

该命令是可选路线；首次 npx 可能下载运行 CLI，服从环境的执行与网络权限。无 CLI 时使用网页检索，不为本次学习强制安装工具。无需运行 skills add：选择学习源与安装技能是不同操作。

## 核对并排序

先判断是否真能教用户想学的工作，再在相关候选中优先高星、受欢迎且经验实质丰富的内容。打开 SKILL.md 和有代表性的参考或示例，检查是否只是工具接口封装。

仓库星数属于整个仓库；单个 skill 的安装量属于对应平台条目。分别记录来源、查询日期和统计口径。一个合集的星数不能写成某组件独享的星数；同一仓库的组件也不能因共享热度重复霸占候选列表。

默认呈现 3–5 个有区别的候选，实际不足时如实呈现。表中包含：

| 编号 | skill 与作者/仓库 | 能学的具体工作 | 新手基础要求 | 仓库星数及来源 | 平台热度及来源 | 选择理由与局限 |
|---|---|---|---|---|---|---|

在名称处链接到具体技能源；热度标注查询日期。拿不到的值写“未核实”，不用 0 代替。避免给出“全网最高星”等未经全面验证的排名。高热度表示关注程度，不能单独担保经验正确。

给出首选建议，询问用户选择哪项；此时结束发现阶段，不提前深度提炼所有候选。用户已指定 skill 时跳过整段候选选择。

## 能力受限时

联网失败如实说明，可列出本地已安装且相关的材料供选择，但不能称其为实时高星榜。明确名称却无法取得内容时，请用户提供链接、路径或文件；不从介绍页猜测深层经验。
